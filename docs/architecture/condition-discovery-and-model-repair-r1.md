# GRCR R2｜必要条件发现、检验与规划模型修复
日期：2026-10-30。性质：**文献研究与待检验协议**；尚未实现 Agent 或运行《巨楼》工程实验。

## 一、关键区分：相关不等于必要
对给定目标 G，LLM 生成的依赖只是候选假设。每个条件必须区分：
- goal-necessary：给定目标和上下文下的必要条件；
- solution-specific：选定某个技术方案后才必需的条件；
- optional：提高质量或效率但非必要的条件；
- related-only：仅在知识上相关，不能直接成为任务。
例如，管道怪物需要某种可执行的穿越路径，但未必需要 NavMesh；独立导航图更不能在不了解现有建筑模型时被默认新建。

## 二、逆向发现的六步研究程序
1. **定义可验收目标**：把创作意图分成可观察运行行为、技术条件与需要真人判断的体验条件。
2. **生成多种可行方案族**：先考虑替代路径，避免沿模型第一个熟悉技术无限深挖。
3. **逆向形成 AND/OR 条件**：每条依赖注明所属方案、适用上下文和不确定性，禁止把可选方案错标为必要条件。
4. **外部寻找隐含前提**：查官方技术资料、真实案例、开源实现、既有项目事实及反例；重点询问已有方案的适用和失效条件。
5. **匹配已有能力**：用项目事实索引、工具能力目录、经验库判断 satisfied/unsatisfied/unknown，未知不等于缺失。
6. **验证与修复模型**：实验失败时定位缺失前提、错误依赖、错误项目事实或不兼容方案，而不是盲目增加新模块。

## 三、工具与 LLM 的边界
| 工作 | 外部工具优先 | LLM / 用户负责 |
|---|---|---|
| 代码/资源已存在？ | LSP、Roslyn、Unity AssetDatabase、Git | 判断业务语义与复用可能 |
| 条件能否形式化检验？ | 约束检查、模拟器、专门规划器 | 创建候选表达和解释失败 |
| 已有解决方法？ | 搜索、论文索引、官方文档、开源项目 | 评估方案的适用条件 |
| 体验能否接受？ | 试玩观察、事件记录、录像 | 解释证据，用户做重要创作取舍 |

## 四、三个容易出错的依赖
- **错误必然性**：将实现方案的局部要求误认为所有方案通用的前置条件。
- **隐含环境假设**：觉得代码逻辑连通就等于角色实际能穿过 Collider 和动态障碍。
- **重复满足**：已有建筑系统负责开口与连通性，却重新创建独立的门洞/拓扑权威。

## 五、条件节点建议字段
goal_id、acceptance、context_constraints、candidate_solutions、condition_statement、condition_kind、status、supporting_evidence、contradicting_evidence、related_capabilities、next_verification、stop_condition。
每个“必须”都应有作用域、证据和可反证条件，不可仅靠模型自信程度。

## 六、来自真实研究的启发（不夸大适用性）
- ACL 2025：LLM 可将自然语言形式化为规划模型并交给现成规划器，但模型生成本身需要检查。https://aclanthology.org/2025.findings-acl.1291/
- ACL 2025：自然语言到形式规划存在边界，需注意错误/不完整的条件表达。https://aclanthology.org/2025.acl-long.242/
- IJCAI 2025：错误规划模型的修复是独立研究方向，不应假设先验模型完美。https://ijcai.org/proceedings/2025/1152
- ICLR 2025：在研究的规划任务中，可靠外部验证比模型单纯自我批评更有效。https://proceedings.iclr.cc/paper_files/paper/2025/hash/f3c5e56274140e0420baa3916c529210-Abstract-Conference.html

## 七、验证设计
给普通模型和受 GRCR 引导的同一模型分别提供门/建筑、管道怪物和经济选择三个目标。分别统计：必要条件召回、错误必要条件比例、已有能力正确复用率、成熟方案匹配、无关探索成本及真实集成结果。故意设置“NavMesh 必须使用”等错误前提，检测模型是否主动反证。
此文档是研究规则，**不能据此声称系统已经具备自主发现未知条件的能力**。
