# GDKM-Production｜生产调用链 R1

## 目标
把“用户提出需求”转换成专业工作，而不是让 LLM 在一个局部问题中无限新增脚手架。

## 任务类型与不同工作模式
| 类型 | 组织方式 | 主要交接/验证 |
|---|---|---|
| 已明确规格的资产 | 分专业顺序交接 | 文件规格、尺寸、导入/运行 |
| 探索性玩法 | 短周期原型与试玩 | 明确假设、试玩证据、退出条件 |
| 复杂跨专业功能 | 联合评审、同步集成 | 统一领域模型、接口、实际场景 |
| 内容量产 | 模板、批量生产与自动检查 | 一致性、预算、抽检 |
| 故障排查 | 从证据出发的定位与回归 | 可复现错误、修复证明 |
| 跨系统集成 | 依赖梳理、持续可玩构建 | 贯通玩家流程与回归测试 |

## 生产调用链
1. 获取用户目标、授权边界、当前工程事实。
2. 明确 **生产对象** 与可验收体验（不直接从功能名生成 Manager）。
3. 查询现有代码、资产、空间关系和既有决策。
4. 识别相关专业、隐含工序、上下游和实际未知。
5. 区分创作歧义（问用户）、专业未知（查资料/实验）、条件充分（执行）。
6. 选择生产模式；制定可撤销、尽量小的改动及验收条件。
7. 专业执行与及时集成。
8. 结构/测试/运行/实际玩家体验的分层检查。
9. 复盘并提炼条件化经验；必要时返工或停止深入。

## 主动性应有的停止条件
- 当前阶段标准已经达到，即使局部还可优化；
- 新工作无法连接可验证的整体产物；
- 引入重复权威数据、抽象层和硬编码风险；
- 现有证据不足，需先做范围受控的实验；
- 触及用户未授权的创作或高影响改动。

不要把每个专业角色机械对应一个 Agent。
