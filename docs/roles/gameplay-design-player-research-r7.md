# GDKM-Role R7｜Gameplay Design × 玩家研究 × 原型验证

日期：2026-10-30。状态：根据游戏用户研究实践及 Ubisoft 官方资料形成的**岗位—工序—外部工具映射**，尚未在《巨楼》开展测试。来源中明确的事实与我们提出的 Agent 方案分开说明。

## 关键发现

- **“游戏有问题”不是直接可执行的诊断**。先确定想了解的具体问题，辨别“发生多少次”与“为什么发生”，再决定方法。Games User Research 的 Steve Bromley 明确提倡先确定研究目的，再从观察、访谈、分析数据、问卷中选择方法。
- **玩家做了什么 ≠ 玩家为什么做**。操作遥测更适合测量事件、路径和退出点；观察和采访用来理解误解、动机和体验。两者的解释不能互相替代。
- **QA ≠ 玩家研究**：QA 核查预期行为与缺陷；玩家研究调查真实玩家如何理解、使用和感受游戏。一次会话可以兼顾，但必须标明不同目标。
- **原型不是为了尽快搭一套完整框架**，而是以最低成本回答当前关键的设计不确定性。
- Ubisoft 官方材料确认其用户研究覆盖开发到上线，包括行为测试、可用性评估、问卷，部分原型甚至未达到技术可玩状态时就可进行研究。参见下方来源。

## 2. 纵向工序：从设计疑问到可执行决策

**D01 描述目标体验**：玩家应有何种可观察的行为/感受？例如《巨楼》玩家遭遇强敌时，应考虑躲避与撤离，而不是直接冲上去战斗。

**D02 生成可证伪问题**：玩家是否发现备用出口？为何不躲进隔间？是否误解怪物的巡逻信息？不要只问“好玩吗”。

**D03 研究方法选择**：度量频率/路径→事件分析；理解原因→观察/访谈；对整体体验→混合方法。方法先于工具。

**D04 制作最小原型**：只实现足以回答问题的环境和行为。定义原型结束后保留、推翻或改进的条件。

**D05 试玩采集**：记录版本、测试任务、玩家背景、事件和观察；尽量避免主持人的提示改变玩家行为。

**D06 分离事实与解释**：事实“3 次无提示下未注意到门”不等于因果“门的材质太暗”。解释须作为假设，由新证据验证。

**D07 优先级裁定**：考虑目标体验、受影响玩家、问题严重性、修复成本与后续依赖；可暂缓局部问题。

**D08 设计迭代与回归**：决定改机制/反馈/关卡/教程/数值中的哪一层；重新测试，防止仅修复表象。

## 3. 具体区分四类工具能回答的问题

| 工具/方法 | 可靠提供 | 不能直接推出 |
|---|---|---|
| 确定性玩法模拟 | 规则可达状态、资源极端、平衡的部分数学性质 | 真实玩家是否有趣 |
| 事件/漏斗分析 | 达成顺序、耗时、离开/失败的统计 | 离开是困惑、无聊还是刻意决策 |
| 观察/录像 | 玩家行为与卡点 | 没有追问就能知道动机 |
| 访谈 | 玩家主观解释、理解与期望 | 所有玩家真实行为或可靠频率 |
| 自动化测试 | 规则/交互是否按实现预期运行 | 游戏体验是否实现创作意图 |
| LLM 综合分析 | 提出候选解释、未测假设、干预方案 | 直接代替玩家或把假设变事实 |

特别注意：要求玩家大声思考可能增加认知负担，改变游戏表现；测试提问需避免暴露目标操作。

## 4. 《巨楼》适用的最小研究案例（尚未测试）

**待验证假设**：当玩家第一次在夜间后门区域遭遇不可正面对抗的强大巡逻力量时，是否能理解“应避开主路，利用室内/管道寻找安全路线”？

- 原型：一个有主路、危险巡逻、至少一条绕行路线的灰盒区域；不需要完整十层楼。
- 可记录事件：进入区域、发现巡逻、交战、躲避、首次使用旁路、死亡/撤回、退出尝试。
- 观察重点：看见什么、停在哪里、是否误读提示、何时发现替代路线。
- 研究问题：能否不被提示地识别危险与替代路线？失败是“不知道该做什么”，还是“知道但选择冒险”？
- 修正路径：环境线索、敌人演出、风险反馈、实际通路可用性、规则本身，不默认增加教程。
- 验证：再次让新的玩家尝试，记录同类事件、理解与感受是否改善。

### 主动问题发现规则（本项目提案）
1. 测试行为与目标行为不一致 → 先记录偏差，不直接猜因。
2. 事件漏斗出现异常断点 → 请求观察该段录像/场景并提出竞争假设。
3. 玩家重复失败却给出“知道做法”的解释 → 重点查手感/执行难度，而不是增加提示。
4. 玩家能顺利通过但觉得无聊 → 自动通过不是体验成功，须研究有效决策与反馈。
5. 新功能缺乏任何对应的用户体验问题或验证目标 → 触发“是否继续开发”的审查。

## 7. 仍需研究

- 真实制作组如何将玩法原型结果转化为是否继续开发的决策；要求有时间、场景和结果的完整复盘。
- 玩家研究与游戏设计师之间怎样避免“仅凭少量样本过度修改设计”。
- 个人项目如何最低成本组织不带引导的试玩并进行可追溯分析。
- 不同玩法（搜打撤、规则怪谈、经营、CRPG）的体验验证指标如何区别，不能机械复用留存率/转化率。
