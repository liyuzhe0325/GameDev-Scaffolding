## 每个岗位的研究卡（每张卡单独一个文件）
- 岗位名称、细分角色、实际团队规模差异
- 工作对象、职责边界、真实一天/一周的活动
- 上游输入 → 专业操作 → 交付物 → 下游接收者
- 必要知识、隐含决策、错误案例、如何识别完成
- 常用软件/插件/网站；哪些检查能由非 LLM 工具代劳
- 与其他岗位冲突时的职责/状态权威归属
- 真实项目证据、出处、证据类型、适用边界
- 未解决问题与需额外验证的假设

## 第一批纵深课题
1. Gameplay 程序员如何在已有大型代码库增加新功能，而不重复架构。
2. 关卡设计师如何将空间意图转交给工具/引擎/AI 导航。
3. 技术美术师如何定义模型、骨架、动画与导入校验。
4. 制作人和 QA 如何识别“模块完成、整体不可玩”的风险。

**核心问题**：哪些职责由 LLM 推理，哪些由 IDE/LSP/Roslyn/Unity/Blender/测试系统提供可检验事实？
