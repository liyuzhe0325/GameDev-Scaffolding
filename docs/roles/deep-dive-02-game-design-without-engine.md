# 深度专题 02｜不依赖 Unity 源码的 Gameplay 设计与问题发现

日期：2026-10-30。状态：经一手资料支持的理论与工具研究；其中《巨楼》例子为**设计推演，尚未做玩家或模拟实测**。

## 问题

如何在不编写游戏引擎代码的情况下，可靠地判断机制设计是否具有潜在价值、系统间是否存在失衡、玩家是否理解规则，以及当前应当解决什么问题？

这不是要求 LLM 在脑中运行完整游戏，而是把机制形式化、数学模拟、行为观察与主观体验证据分别交给更适合的工具和研究方法。

## I. 理论：MDA 的作用及边界

Hunicke、LeBlanc、Zubek 的 MDA（2004）将设计区分为 Mechanics、Dynamics、Aesthetics。重要的是两个方向的推导：

- 从设计者角度：**Mechanics → Dynamics → Aesthetics**，规则经互动产生体验。
- 从玩家角度：体验是玩家最先接触的表面，玩家不一定理解底层规则。

实际应用时，不能将“新增规则”直接等同于“增加有意义的体验”。必须提出可观察的动态假设：例如增加一种撤离成本，是否真的促使玩家更早停止搜刮？

**方法局限**：MDA 的概念不是严格数学定理，也不能单凭模型推演玩家感受；后续学术工作批评其边界并非完全严密。

资料：
- AAAI 2004 原始论文：https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/
- 对 MDA 边界的讨论：https://www.mdpi.com/2078-2489/12/10/395

## II. 工作对象：有意义的玩家决策

不要先列功能表，应列一段玩家决策：

- 玩家知道什么？哪些信息隐藏/失真？
- 允许做哪些行动？行动有什么成本？
- 玩家有什么短期/长期目标？
- 什么会令当前最优策略改变？
- 决策的反馈在何时出现、是否可理解？
- 是真的存在选择，还是某个选项在所有条件下都严格占优？

### 示例：《巨楼》一次“继续探索 or 撤离”

假设玩家已有价值为 V 的物资；继续探索存在概率 p 的失败风险与收益 R；撤离可以安全带回已有物资。简单的期望比较：

- 撤离期望 = V
- 继续期望 = (1-p)(V+R) + p L

其中 L 是失败后仍可得到的价值（可能为 0、负损失或其他机制）。继续的期望优于撤离当且仅当
(1-p)R > p(V-L)。

这不是游戏最终设计公式，只是一个能暴露**隐藏设计前提**的简化模型：
- 玩家真的知道 p 吗？
- 风险是否随资源、时间和状态变化？
- SAN、可复活机会、情报和派系会改变 L 吗？
- 如果 p 和 R 固定，玩家是否形成机械最优策略？
- 玩家体验是否由非期望效用因素（风险厌恶、情绪、探索动机）主导？

计算只能揭示数学结构，不能证明玩家会按期望值行事。

## III. 独立于 Unity 的专业工具

| 任务 | 可复用工具/方法 | 能够提供的证据 | 无法回答 |
|---|---|---|---|
| 拆解体验目标/机制/行为 | MDA + 结构化决策记录 | 关键假设及规则联系 | 真实玩家是否产生预期感受 |
| 资源流与经济 | Machinations（资源池、来源、消耗、转化、随机门、蒙特卡洛） | 给定参数的系统运行与分布 | 人类策略变化和叙事情绪 |
| 规则一致性 | 决策表、状态机、性质测试/形式约束 | 不变量、矛盾和不可达状态 | 所有现实操作情景 |
| 数值鲁棒性 | 参数扫描、随机模拟与敏感性分析 | 对假设改变的敏感程度 | 玩家是否理解风险 |
| 玩家真实行为 | 无提示试玩观察、视频记录、访谈 | 行为/理解与体验证据 | 小样本的全体玩家比例 |
| 反馈分析 | 本地事件分析/漏斗/问卷 | 行为频率和故障位置 | 直接归因 |

## IV. 从“发现问题”到“选择研究方法”的完整过程

**D-01 明确体验承诺**：用玩家行为与情绪表述目标，而非罗列系统。例如“玩家在资源高收益与撤离风险间反复犹豫”。

**D-02 建最小决策图**：状态、信息、行动、成本、后果、反馈。不急着写故事或具体脚本。

**D-03 提出可证伪的候选问题**：
- 某行动在绝大多数状态严格优于其他行动吗？
- 玩家是否缺乏足够信息做出符合设计意图的决策？
- 新机制是否只新增操作负担，未改变任何最优选择？
- 不同子系统是否对同一资源生成冲突激励？

**D-04 选择证据方法**：代数/模拟/状态检查优先于 LLM 猜测；涉及心理与理解时必须获得真实玩家证据。

**D-05 做低成本实验**：纸面决策、表格、抽象模拟、试玩脚本；明确实验结束条件。

**D-06 对照结果与反事实**：若结果与预期不同，保留多种解释，不能从一次失败直接断定原因。

**D-07 做取舍并记录**：修改规则、调整可观测反馈、重新设计选择或暂缓。保留被拒绝方案与依据。

**D-08 回归体验目标**：新机制要证明改善了整体玩家决策，而不仅是模拟数值更平滑。

## V. 不需要代码的第一项可执行实验

主题：《巨楼》撤离决策的激励结构。

准备 4 组情境：
A. 低库存、低危险；B. 高库存、低危险；C. 高库存、高危险；D. 低库存、高危险。

分别改变：物资价值 V、额外奖励 R、失败概率 p、失败后价值 L。

记录：
- 哪些组合出现继续/撤离期望严格占优；
- 哪些组合临界接近，让玩家真正需要权衡；
- 变化 p、R、L 时行为阈值是否极其敏感；
- 如果玩家不知道 p，需要什么信息反馈；
- 一旦引入 SAN/复活/异常规则，哪些初始假设不成立。

**注意**：以上实验的公式只是说明机制分析方法。它不能直接替代完整的风险评估，也不应擅自把《巨楼》的 SAN 归零设定改成失败撤离。

## VI. 提供给 Agent 的“问题发现触发器”

- 新增机制，却未指出它将改变哪个玩家决策 → 暂停并询问/研究；
- 某选项跨多数状态无条件最优 → 检查策略空间是否退化；
- 两个系统围绕同一资源存在激励冲突 → 进行系统整体模拟；
- 数学结果稳定但真实玩家反馈不同 → 转玩家研究，而不是继续调数值；
- 试玩记录表明玩家不理解目标 → 先区分缺信息、误读、操作困难及主动风险偏好；
- 即将投入高成本内容生产而核心行为假设未经验证 → 优先低成本原型。

## VII. 下一步深入而不是换岗位

1. 完整研究“选择与策略空间”的数学结构：严格支配、帕累托取舍、风险厌恶与信息价值；
2. 研究一个真实游戏开发者从纸面原型到试玩修改的完整案例（带时间、失败和修正）；
3. 用 Machinations 或表格针对同一设计问题建立可复现模拟，并把参数与结果存档；
4. 制定决策设计的标准记录卡，验证 Agent 能否主动发现无效选择和系统冲突。

**本篇不主张创造新的游戏设计工具；优先使用成熟模拟与研究方法。**
