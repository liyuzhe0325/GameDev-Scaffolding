# 横向研究待办 R2

目标：从岗位概述走向真正的专业操作、工具、质量标准和真实经验。优先跨专业接口密集、易产生返工的环节。

| ID | 研究对象 | 核心深挖问题 | 实证要求 |
|---|---|---|---|
| ROLE-01 | Gameplay 程序 + 系统架构 | 怎样防止局部功能复制原有领域对象与权威状态？ | 源码级实际案例与对照测试 |
| ROLE-02 | 关卡设计 + AI 导航 | 空间规则如何由设计意图转为可验证的导航条件？ | 关卡灰盒与运行场景 |
| ROLE-03 | 技术美术 + 资产工程 | 模型/材质/动画导入规格如何固化成工具检查？ | Unity/Blender 原生 API 实测 |
| ROLE-04 | 技术动画 + Gameplay | 骨架、动画和控制器的交接如何减少滑步/错姿？ | 角色演示与运行证据 |
| ROLE-05 | 工具工程师 | 何时用成熟工具、何时开发专用工具，如何验证收益？ | 一手工具设计案例和成本评估 |
| ROLE-06 | QA + Build | 谁以及如何持续维护可运行的整体构建？ | CI/回归/故障复现案例 |
| ROLE-07 | Gameplay 设计 + 试玩研究 | 设计规则与实际玩家反馈之间怎样形成迭代？ | 真实试玩/数据案例 |
| ROLE-08 | 叙事 + 关卡 + 交互 | 规则怪谈的叙事信息如何成为可理解的玩法？ | 成熟作品的真实制作过程 |

研究输出按“岗位/操作/输入/输出/工具/自动验证/需要判断/交接/失败案例/来源”逐项拆分。不能以岗位名称列表代替证据。
