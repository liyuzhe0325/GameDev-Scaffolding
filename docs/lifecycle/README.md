# GDKM-Lifecycle｜纵向工序地图 R1

状态：研究结构；下列阶段是参考分类，实际并非线性瀑布。

## 十个参考阶段
| ID | 阶段 | 主要可检验产物 | 常见决策门 |
|---|---|---|---|
| L01 | 概念与立项 | 创作支柱、目标体验、范围假设 | 值不值得验证？ |
| L02 | 可玩原型 | 可直接操作的核心机制 | 核心行为成立吗？ |
| L03 | 预制作 | 工作规范、技术风险实测、资产模板 | 能稳定复制生产吗？ |
| L04 | 垂直切片 | 跨专业完整质量样本 | 品质与成本可承受吗？ |
| L05 | 正式生产 | 迭代内容、持续可玩构建 | 产出是否可靠集成？ |
| L06 | Alpha | 核心流程与功能贯通 | 是否具备完整功能面？ |
| L07 | Beta | 稳定性、可用性和体验修正 | 剩余风险是否可控？ |
| L08 | 发布候选 | 版本锁定、回归与发布检查 | 是否满足发布要求？ |
| L09 | 发布 | 发布版本、监控和响应机制 | 发布是否正常？ |
| L10 | 维护/复盘 | 修复、反馈与经验记录 | 哪些经验值得复用？ |

## 每项工序要研究
**阶段 → 工作流 → 任务 → 专业操作 → 验收/决策**，记录前置条件、责任专业、输入数据、实际工具、产物、自动检查、人工试玩、风险、返工路径及停工条件。

## 外部化能力的候选
- 项目/进度：GitHub Issues、依赖图、构建工件与版本标签。
- 工程：Roslyn/LSP、架构约束、Git 变更审查。
- 内容：Unity AssetDatabase、Prefab/Scene 依赖、Blender Python 校验。
- 运行：Unity EditMode/PlayMode tests、Profiler、自动化场景记录。
- 设计与体验：结构化试玩记录和遥测；不能把主观体验简化为测试通过。

## 跨阶段的关键约束
- 始终保留可运行的整体流程（阶段不要求同等品质）。
- 原型验证问题，而不自动扩展为通用框架。
- 风险先验证；探索要有退出条件。
- 技术完成、内容完成、整体体验完成要分别验收。
