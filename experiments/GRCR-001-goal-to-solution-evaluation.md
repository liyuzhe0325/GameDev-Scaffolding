# GRCR-001｜逆向条件发现与成熟方案复用：评测设计

**状态：实验方案，未执行。** 不得宣称已提升正确率。

## 目标和可检验假设

假设：在同一任务和项目事实下，引入“目标验收→逆向依赖→条件匹配→专业工具/方案检索”协议，能减少必要条件遗漏和重复造轮子，同时不过度增加工具与搜索成本。

## 三个初始测试问题

### E1：门与建筑
目标：给已有建筑系统增加开闭/锁定门，而不复制空间拓扑。

隐藏关键条件：检查既有构件注册、房间连接、实际门状态、AI 导航、Prefab/Scene、状态读写权威。

关键判错：完全未查现有 Building/Opening/Connectivity 就新建独立拓扑；或粗暴合并两套实际上语义不同的图。

### E2：管道追逐怪物
目标：特殊体型怪物能正确追逐玩家穿过狭窄管道。

关键条件：目标感知、通行能力、不同姿态碰撞体积、运动与动画、路径连接、失败后状态转换、玩家反馈。

关键判错：只把普通 NavMesh 加入场景就宣告完成；或无证据自研一整套通用 3D 导航框架。

### E3：经营资源循环
目标：提供在玩家体验上有意义的资源生产与消费选择。

关键条件：参与方和资源守恒、激励差异、可理解反馈、相互影响、简单模拟、玩家验证。

关键判错：只优化数值表没有真正差异化决策；或无需实证直接发明复杂经济仿真。

## 两组对照

- A：普通 LLM/编码 Agent，自然语言目标、等量工程访问和搜索能力。
- B：同模型同任务同权限，在提示和工具界面上增加 GRCR 逆向条件/能力检索协议。
- 尽可能固定起始提交、模型版本、Token 和时间预算；重复实验，记录差异。
- 实际源码/Unity 工程测试由有本地访问权的 Codex 执行；当前设计阶段不假定已经拥有真实工程数据。

## 评分表（判定规则）

| 指标 | 度量 | 说明 |
|---|---|---|
| 条件召回 | 重要必要条件被发现的比例 | 参考答案由独立专业检查确定，可允许合理替代路线 |
| 假必要条件率 | 被错误标为“必须”的项目比例 | 防止搜索/功能膨胀 |
| 已有能力匹配 | 对已有系统/工具可复用部分的正确识别 | 必须附来源证据 |
| 结构冗余 | 重复维护权威事实、无价值抽象数量 | 不按新增类数机械评分 |
| 集成质量 | 可验证行为、回归、跨系统一致性 | 不能只看单测 |
| 搜索效率 | 检索步数、Token、无关文献比例 | 无限制搜索不能得高分 |
| 结束时机 | 是否在目标满足后及时停止 | 包括必要例外 |
| 经验可复用性 | 记录触发条件、来源和反例 | 不把一次观察夸大为通则 |
